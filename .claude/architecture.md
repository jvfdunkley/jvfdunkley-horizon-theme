## Overview

This is a Shopify theme. It uses Webpack Encore for asset compilation with Tailwind CSS, SCSS, and PostCSS.

## Development Commands

```bash
yarn dev              # Run watch + Shopify dev server concurrently
yarn watch            # Watch mode for asset compilation only
yarn build            # Production build
yarn shopify:dev      # Shopify theme dev server (store: 813fbc-3f)
```

## Linting, Formatting & Checks

- **Code Formatting**: Prettier (configured in `.prettierrc`)
- **JavaScript**: ESLint (configured in `.eslintrc.js`, extends Prettier to avoid conflicts)
- **Liquid/Theme**: Shopify Theme Check (configured in `.theme-check.yml`, includes accessibility rules)

```bash
npm run format        # Format all files with Prettier
npm run format:check  # Check formatting without writing
npm run lint          # Run ESLint on JS files
npm run lint:fix      # Run ESLint with auto-fix
npm run theme:check   # Run Shopify theme check
```

## Theme Architecture

### Directory Structure

- `src/` - Source JavaScript and SCSS (compiled to assets/)
  - `entrypoints/` - Webpack entry points
  - `modules/` - Modular code imported by entry points
- `assets/` - Compiled output + vendor libraries (entry-_.js, entry-_.css)
- `sections/` - Shopify section files with schema definitions
- `snippets/` - Reusable Liquid components
- `templates/` - JSON page templates
- `layout/` - Base layouts (theme.liquid, password.liquid)
- `locales/` - Translation JSON files

### Build Pipeline

- Entry: `src/entrypoints/global/index.js` → Output: `assets/entry-global.js` + `assets/entry-global.css`
- Webpack alias `@` maps to `./src/`
- Tailwind scans all `.liquid` files and `src/**/*.js` for classes

### Git Workflow

**Pre-commit hooks** (via Husky + lint-staged):

1. Removes `assets/entry-*` from staging (compiled assets are generated by CI on master branch)
2. Runs Prettier on staged files (JS, JSON, CSS, SCSS, MD)
3. Runs ESLint on staged JS files (with auto-fix)
4. Runs Shopify theme check (validates Liquid, accessibility, translations)
5. Runs production build (`npm run build`)

**CI/CD** (GitHub Actions):

- `compile-assets.yml`: Builds and commits compiled assets on master
- `lighthouse.yml`: Runs Lighthouse performance/accessibility audits (manual trigger with preview URL, or theme check on PRs)

Do not commit compiled entry files locally.

### Key Architectural Patterns

**Section Groups**: The theme uses section groups for modular header/footer composition:

- `sections/header-group.json` - Defines header structure with announcements and main navigation
- `sections/footer-group.json` - Defines footer structure with content blocks and utilities
- Referenced in `layout/theme.liquid` via `{% sections 'header-group' %}` and `{% sections 'footer-group' %}`

**JSON Templates**: Pages use JSON-based templates that compose sections and blocks:

- Templates define which sections appear on a page and their settings
- Each section contains blocks with specific configuration
- Example: `templates/index.json` has sections for hero, marquee, email signup, etc.

**Component System**: JavaScript uses a custom component base class:

- `assets/component.js` provides base `Component` class extending `DeclarativeShadowElement`
- Manages element references via `ref` attributes
- Handles mutation observers for dynamic DOM updates
- Individual components extend this base (e.g., `cart-drawer.js`, `header.js`)

**Color Schemes**: Theme uses a color scheme system defined in `config/settings_schema.json`:

- Multiple color schemes with roles for text, background, buttons, inputs, variants
- Each scheme defines colors for default, hover, and selected states
- Applied to sections via `color_scheme` settings

**Settings Schema**: The `config/settings_schema.json` file defines all theme customization options:

- Typography (4 font families: body, subheading, heading, accent)
- Colors (color scheme groups with detailed role definitions)
- Layout (page width: narrow/normal/wide)
- Animations (page transitions, hover effects, add-to-cart animations)
- UI components (badges, buttons, inputs, drawers, popovers)
- Product cards, cart, search, swatches, and variant pickers

**Block Types and Reusability**: Sections support multiple block type approaches:

- **Custom blocks**: Defined in the section's schema with specific settings (e.g., `rotating_text`, `static_text`)
- **`@theme` blocks**: References to globally available theme blocks (e.g., buttons, headings, images)
- **`@app` blocks**: Third-party app blocks that can be embedded
- **CRITICAL CONSTRAINT**: You CANNOT mix custom blocks with `@theme` or `@app` blocks in the same section
  - A section must use EITHER custom blocks OR `@theme`/`@app` blocks, not both
  - Mixing them will cause Shopify error: "Theme blocks and section-defined blocks can not be used together"
  - If you need `@theme`/`@app` functionality, define the section with ONLY `@theme` and `@app` blocks
  - If you need custom blocks, do NOT include `"@theme"` or `"@app"` in the blocks array
- Leverage `@theme` and `@app` blocks to reuse existing functionality instead of creating custom implementations
- In schema, include `"@theme"` and `"@app"` in the blocks array to allow theme/app blocks
- Render these blocks using: `{% render block.type, block: block %}`

### Localization

The theme supports extensive internationalization:

- Default locale: `locales/en.default.json`
- Both `.json` (translations) and `.schema.json` (theme editor translations) files
- Translations accessed via `t:` prefix in Liquid (e.g., `t:names.footer`)
